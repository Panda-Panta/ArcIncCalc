# 明日方舟基建自动排班优化器详细计划书

日期：2026-09-08；适用分支：`mode/shift-run`。本计划面向“在可信事件模拟器之上自动生成最优或较优排班”，不会以旧静态估算器作为优化目标。

## 一、目标与退出条件

优化器接收账号可用干员、培养阶段、基建设施、初始心情与库存、Mower 策略约束、无人机和收取日程，输出可导回 Mower 的主排班、跑单候选、菲亚梅塔目标和可解释交接时间表。

第一阶段追求在固定设施布局下稳定地产生“可执行且优于基线”的排班；第二阶段求近似 Pareto 前沿；只有在小规模实例上有可证明上界并达到零间隙时才使用“最优”一词。

发布门槛：所有方案通过干员唯一占位、床位容量、候选可用、资源守恒和 Mower 协议校验；在至少 252 二赤金、252 三赤金、342 纯钱、342 搓玉四类登记场景中，固定预算内不劣于人工基线；同一输入、规则版本、种子和预算得到相同结果。

## 二、先决条件

1. event-v2 完成心情、换班、菲亚梅塔、订单、库存、仓储、无人机和收取事件闭环，并通过手算、守恒及长期收敛测试。
2. 规则覆盖表把参与候选的技能标记为 `exact`、`approximate` 或 `display-only`。默认禁止优化器把 `display-only` 当作零效果；用户可选择排除该干员或采用带惩罚的保守估计。
3. 输入显式给出精英阶段、技能解锁、可用干员、初始心情、氛围、库存、操作耗时和人工在线窗口。缺失参数必须在求解前固化为可见假设。
4. 252 外部表格只作参考；先核验公式与口径，再决定数值容差。优化器不得通过样本专用常数拟合表格。

## 三、问题分层

### 1. 静态布局层

变量包括每座制造/贸易站产品、常驻组合、控制中枢与功能设施人员、无人机目标。约束包括设施容量、电力、干员唯一、技能前置、产品合法性和用户锁定项。

静态层使用约束规划或混合整数规划产生若干高质量种子。直接效率、容量、电力及明确的同站加成可线性化；复杂联动以预计算组合列表示，避免为每个技能写求解器特例。

### 2. 轮班模板层

变量包括岗位有序候选、原子换班组、宿舍 Free/VIP 位、菲亚梅塔目标顺序、心情上下限和常驻策略。约束由事件运行时验证，不在静态阶段把共享候选错误视为同时占岗。

此层采用约束引导的大邻域搜索：交换整组、替换候选、调整候选顺序、移动宿舍优先级、拆分或合并换班组。每次变异先做廉价可行性检查，再进入短窗口仿真。

### 3. 连续时间策略层

变量包括换班阈值、跑单提前量、收取时点和无人机分配。订单获取开始、完成与交付分别建模；跑单动作只能作用于允许的订单阶段。

连续参数先在安全离散网格上搜索，再对前若干方案用局部无导数优化。所有参数取值都要能转换为 Mower 可表达的配置或明确的外部操作计划。

## 四、目标函数

默认使用词典序目标，避免用一个隐藏汇率混合所有资源：

1. 最小化不可执行事件、空岗时间、资源透支和未量化规则风险；任何硬约束违反直接淘汰。
2. 在用户选择的生产目标下最大化长期可交付量，例如贸易龙门币、EXP、合成玉或赤金净增长。
3. 最小化人工操作次数、夜间操作、换班次数和对初始库存的依赖。
4. 最大化鲁棒性：在登录延迟、收取延迟、初始心情误差和订单随机分支变化下保持收益。

用户可选择多目标模式，输出收益、操作负担、风险三维 Pareto 集；每个方案显示相对当前排班的增量和置信区间。EXP 与龙门币换算仅在用户显式提供汇率时启用。

## 五、候选生成与加速

1. 预计算每名干员在合法设施/配方/培养阶段下的直接效果和依赖标签。
2. 按同站联动、阵营资源和全局状态生成小规模组合列；用支配关系删除在所有登记场景中更差且成本不低的组合。
3. 从用户当前排班、常见人工组合和静态求解器结果形成多样化种子。
4. 使用两级评估：解析上界或短窗口近似筛掉明显较差方案，完整事件模拟只评估前列候选。
5. 缓存以规范化方案、数据版本、规则版本和假设哈希为键；事件结果含随机订单时还必须包含确定性分支集或种子。
6. 对局部变异做增量重算，只失效受影响房间、联动资源和后续事件；每次发布前用完整重算抽检缓存正确性。

## 六、不确定性与随机订单

正式排名优先采用有限订单分支的确定性传播或多种固定种子共同随机数。概率质量剪枝必须报告丢失上界；蒙特卡洛报告样本数、标准误和置信区间，不能把单条路径当期望值。

鲁棒评估至少覆盖：订单品质序列偏移、用户晚收取、跑单换入延迟、赤金初始库存变化、一个关键替补不可用。排名以保守分位数或最坏登记场景为准时，UI 必须显示用户选择的风险口径。

## 七、可解释输出

每个候选方案输出：Mower JSON/JPG、设施与岗位表、替补顺序、换班组、菲亚梅塔筛选原因、跑单事件、无人机策略、资源账本、收敛报告、规则覆盖和相对基线差异。

优化器同时生成“为何选择”和“为何未选择”：列出关键技能贡献、被约束阻止的更高静态效率组合、库存瓶颈、宿舍瓶颈及操作成本。任何近似技能对排名的最大影响单独列出。

## 八、模块与接口

建议新增以下深模块：

- `src/optimizer/problem.ts`：不可变 `OptimizationProblem`，包含账号、设施、目标、约束、假设与版本哈希。
- `src/optimizer/candidate.ts`：规范化 `ScheduleCandidate`、可行性状态和方案哈希。
- `src/optimizer/staticSeeder.ts`：静态约束种子，不调用完整模拟器。
- `src/optimizer/neighborhood.ts`：可逆变异算子和受影响域。
- `src/optimizer/evaluator.ts`：统一调用 event-v2，返回目标向量、风险、覆盖和证据。
- `src/optimizer/search.ts`：预算、停止条件、去重、Pareto 档案和确定性并行调度。
- `src/optimizer/explain.ts`：把求解轨迹转换为可审核说明。
- `src/optimizer/exportMower.ts`：仅输出 Mower 可表达语义；无法表达的操作生成独立执行清单。

核心接口：

```ts
interface OptimizationBudget {
  maxEvaluations: number
  maxWallTimeMs: number
  seed: number
  parallelism: number
}

interface CandidateEvaluation {
  feasible: boolean
  objectives: number[]
  constraintViolations: string[]
  uncertainty: { lower: number[]; mean: number[]; upper: number[] }
  simulationHash: string
  explanation: string[]
}
```

## 九、实施里程碑

### O0：可复现实验框架

冻结输入、规则、假设和求解预算哈希；建立当前人工排班基线、空方案和明显更差方案。验收为重复运行结果完全一致，超时也能返回已验证的当前最优候选。

### O1：静态种子器

只优化设施内常驻人员和产品，不生成动态换班。用小型穷举实例与求解器结果对比，证明可行性和上界；在真实账号上输出前 20 个多样化种子。

### O2：轮班大邻域搜索

加入候选顺序、组事务、Free/VIP 和菲亚梅塔策略。每个变异都有逆操作和不变量测试；固定评估次数内优于静态种子。

### O3：跑单、库存与无人机联合优化

加入订单时点、赤金供需、仓储、收取窗口和无人机。验收为无负库存交付，且对无限库存反事实能解释收益差异。

### O4：多目标与鲁棒搜索

维护 Pareto 档案，加入固定分支集和延迟扰动。验收为同预算下结果稳定、置信区间可复核、操作负担可调。

### O5：产品化与 Mower 导出

增加锁定干员/房间、继续搜索、对比方案、导出前验证和恢复点。导出的每个字段完成 JSON/JPG 往返测试；非 Mower 原生操作不会伪装成可导字段。

## 十、测试矩阵

- 单元：每个变异保持干员唯一、设施容量、候选顺序和输入不可变。
- 性质：随机生成小实例，任何已标可行方案都通过运行时不变量与资源守恒。
- 最优性：小规模实例穷举，比较最优目标和 Pareto 集，不只比较一个预期方案文本。
- 回归：登记人工排班不得退化；新增干员数据时记录前后排名和规则覆盖差异。
- 差分：完整重算与增量重算一致；单线程与多线程结果在固定种子下相同。
- 性能：分别记录候选生成、短评估、完整模拟、缓存命中和内存峰值。
- 故障：预算耗尽、浏览器刷新、worker 崩溃和无可行解时返回最近已验证候选及原因。

## 十一、风险与停止规则

最大的风险是“优化错误的模拟器”。event-v2 未达到金标准前，优化器只能用于实验，不在产品中标注最优。规则为 approximate 时做灵敏度分析；若其影响可能改变前列排序，暂停自动推荐并要求用户确认策略。

搜索空间爆炸通过分层、支配剪枝、预算和增量模拟控制。任何启发式算法都必须保留当前人工排班作为候选，因此即使超时也不会返回已知更差方案。发布数据更新后若覆盖率下降或金标准失败，自动排班功能回退为只读对比模式。
