## 结论

1. 11份 JSON 均可读取和解析；10份可生成完整收益汇总，`342卖玉` 被旧替补投影限制阻断。
2. 只有三张独立工作表提供可直接比较的长期日产。它们的贸易差异很小，经验差异最大，自然赤金居中。
3. 第一张 `排班表` 的其他区块是静态主班/替班效率端点，不能直接当成长期日产。程序制造均值低于这些端点，核心原因是动态轮班模型与 Excel 固定占比不同。
4. 搓玉排班当前会消耗超过日产的源石碎片；在事件引擎加入库存与停机前，合成玉日产属于允许库存透支的理论值。
5. 下一步若要做到逐表精确拟合，需要统一工作占比、Free床位分配、菲亚梅塔交换、无人机投放、订单快照和初始库存，而不是继续调整已确认的静态技能效率。
