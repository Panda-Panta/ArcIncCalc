# Mower 跑单事件基础开发报告

开发模型：`gemini-3.8-flash-high`（Antigravity CLI 会话 `edcdd92f-568d-4465-b66d-44fce06a5b49`）承担主要运行期、适配器、计算桥和测试隔离开发；Sol 完成订单互斥修复、基础事件模块、VIP 床位纠正、文档与最终验证；Terra 进行独立只读复核。

## 已实现

- Vitest 排除 `.worktrees/**`、`.antigravity-bridge/**` 和 `dist/**`，当前分支测试不再混入旧工作树。
- `CompiledSchedule` 无损保留岗位、全量有序候选、分组、Free/Current、主表策略、菲亚梅塔目标、跑单候选、来源工作区与显式假设。
- `scheduleAdapter` 将普通替补与但书/龙舌兰/佩佩跑单候选分流；每个宿舍首个 Free 标记为 VIP 位。
- 运行时提供干员唯一占位、共享候选预约、组换班原子提交、容量受限休息床位、下一心情事件和菲亚梅塔交换基础模型。
- 订单模块分离基础订单选择、获取进度与完成快照；但书和龙舌兰互斥应用。三级普通品质跑单由错误的 `4.9金/2950龙门币` 修为 `4.5金/2350龙门币`。
- 资源账本拒绝库存不足的原子交易并记录流入/流出；仓储报告实际生产与阻塞；无人机记录持有、生成、溢出、消耗和每架 3 基础分钟。
- 计算桥默认保留 legacy；显式请求尚未闭环的 event-v2 时返回 `EVENT_V2_UNAVAILABLE` 与空报告，不输出伪造的新引擎数值。
- 252 二赤金登记输入 LF/原始 SHA256、单位和外部参考值，没有设置虚假容差；同日随后已按 `mower表.xlsx` 第三个工作表的公式与缓存值升级为 `external-verified`。

- TDD 红灯：旧三级跑单四个边界均失败，实得 `4.9金/2950`；修正后订单回归与原计算测试通过。
- TDD 红灯：Free 床位全部为普通位；按每宿舍首个 Free 为 VIP 修正后适配器测试通过。
- 新模块集中验证：11 个测试文件、43 项通过。
- 全量验证：39 个测试文件、383 项通过；`vue-tsc -b` 通过；Vite 生产构建通过；`git diff --check` 通过。
- 构建保留既有前端包体警告：主 JS 约 1.37 MB、gzip 约 441 KB。

## 仍未完成

event-v2 尚未把动态规则效率、制造进度、订单分支、收取、库存和无人机统一积分为 `CalculationReportV2`，因此没有成为默认引擎。菲亚梅塔运行时只覆盖已核实的交换核心与部分 Mower 筛选条件；暖机、全部组策略和真实订单抽取时点仍需来源及实测。252 外部参考的 Excel 公式、库存、无人机和收取口径仍未核实，不能声称数值已与 Mower 对齐。
