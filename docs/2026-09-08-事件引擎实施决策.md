# Mower 产出计算：本轮实施决策

日期：2026-09-08；分支：mode/shift-run。

依据：根目录《明日方舟基建收益预测软件计划书.md》、`docs/用户说明书.md`。用户本轮明确选择“完整开发并验证”。本文件记录实施约束与验收状态，不能代替验证结果。

## 架构选择

沿用计划书的并行迁移方案：无损 Mower 工作区是配置事实源；纯编译器保留完整岗位语义；运行时负责候选可用性和原子换班；事件模拟器推进工作量与资源；报告展示真实已实现的计算模式。旧引擎保留作回归对照，不能把旧结果标记为 event-v2。

原地给一对一适配器追加特殊分支，无法表达共享候选与休息池；整体替换既有规则引擎又会失去原有回归保护。因此采用独立编译器与模拟模块、窄接口复用既有规则的渐进迁移。当前目录已有用户工作，保留现有分支和所有未提交更改，不从旧工作树复制算法。

## 数学与领域边界

1. 时间统一采用小时，订单基础工作量采用分钟，转换只在接口边界完成。资源分别记录 EXP、赤金条数、龙门币、碎片、合成玉与无人机；库存估值与已实现收入分列。
2. 订单的成本、报酬与特殊类型不可随后续换班改变；实时效率只推进可受效率影响的剩余工作量。快照时点以游戏和 Mower 原始证据核定，不能仅凭旧代码命名推断。
3. 静态无限库存长期吞吐采用 E[报酬]/E[时长]。动态库存/排班含非线性边界，不能把平均成本的虚拟订单宣称为精确概率模拟。概率分支必须保留联合状态；状态合并误差、截断或抽样都须显式报告。
4. 收敛有两层：有限状态周期回放与窗口均值稳定。库存可持续增长时完整状态不会重复；需分离可累加资源与影响未来行为的状态，报告库存漂移。均值接近不代表状态周期已证明。
5. 原始主表不包含的参数（初始心情、氛围、库存、收取日程、操作耗时、干员培养阶段）必须有可见默认值和来源；不得从 Excel 输出反推成隐藏常数。
6. 未实现的规则不能自动标记 exact。规则清单需要记录生效条件、来源、适用数据版本与独立用例；复杂联动暂未覆盖时输出诊断和精度边界。
7. 不执行副表、触发器 AST 和 roomTask；只保证无损保存。优化器计划与实际求解器实现分开，本轮目标为详细规划未来求解器。
